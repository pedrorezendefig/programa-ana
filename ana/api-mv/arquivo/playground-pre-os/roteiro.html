Roteiro por zona de banco

Os endpoints da API separados por onde o dado vive, segundo o fato oficial da MV (Dácilla, suporte, 24/jul/2026): a API de agendamento por WhatsApp roda sobre o banco SaaS da Global Health (inacessível ao hospital) e o banco Soul (o Oracle do MV) só é tocado na finalização do agendamento. Zona Soul: dá para conferir no DBeaver, com a query pronta em cada card. Zona GH: não há o que procurar no banco; a conferência é a resposta da API. Toda conferência no banco é manual (o firewall bloqueia consulta automática).

Paciente-sonda: todos os testes usam o cadastro fictício TESTE INTEGRACAO ANA VITTA (CPF 66301102770, id 1681), criado via API na homologação. É o único dado pessoal permitido neste roteiro e nas queries de conferência. Nunca use CPF, nome ou telefone de paciente real.

MÉTODO Antes de começar

  1. Suba o servidor local (python3 ana/api-mv/playground/server.py) e abra a Bancada em localhost:8777: é ela que dispara as chamadas de API.
  2. Para as conferências no banco, conecte a VPN HSM e abra o DBeaver na sua conexão do banco Soul (owner DBAMV). Sempre manual: copie a query do card e cole no DBeaver. Nenhuma query roda sozinha a partir daqui.
  3. Trabalhe pelas zonas: o grupo 01 (catálogo) alimenta os ids que o grupo 02 (finalização) pede. O grupo 03 é a zona GH: dispare quando o fluxo exigir, mas não procure efeito no banco.
  4. Anote cada resultado dos dois lados (resposta da API e linhas do banco). As divergências alimentam as perguntas abertas GH-18, GH-19 e C6-6.

Esta página não chama API nem banco: quem dispara a API é a Bancada, e quem roda SQL é você, no DBeaver.

O mapa das zonas em uma frase: pessoas, carteiras, anexos e respostas de triagem ficam no banco da GH e nunca aparecem no Soul (arquitetura, não falha); o catálogo (itens, convênios, prestadores, agendas) nasce no Soul e a GH espelha; a escrita no Soul acontece só no agendar/reagendar/cancelar. Na IT_AGENDA_CENTRAL existem as colunas CD_IT_AGENDA_CENTRAL_INTEGRA, CD_SEQ_INTEGRA e DT_INTEGRA, hoje 100% vazias: qualquer linha com elas preenchidas é o detector de que a escrita externa chegou neste banco (GH-18).

Objetivo: conferir o que o canal enxerga do catálogo de consultas e comparar com o que existe no MV. Obs.: bloqueado, mensagemBloqueio e ordem são camada da GH (configuração do canal), não do Soul.

  3. Interpretação: se a query traz itens e a API vem vazia, o catálogo existe no MV mas não foi publicado para o canal (GH-19): registre a evidência.

9GET Horários livres /agendas/v2

Objetivo: o coração do fluxo: comparar os horários que a API devolve com os slots livres do MV (pergunta C6-6: como se lê um slot livre).

  3. Interpretação: se a query traz slots e a API responde sem horários, faltou publicar a agenda para o canal (GH-19). Anote toda divergência entre os dois lados: ela alimenta a C6-6.
Query espelho · slots livres de hoje em diante no banco Soul

       ac.DT_AGENDA, ac.CD_PRESTADOR, ac.QT_MARCADOS, ac.QT_ATENDIMENTO
FROM   DBAMV.IT_AGENDA_CENTRAL ic
JOIN   DBAMV.AGENDA_CENTRAL ac

AND    ic.SN_BLOQUEADO = 'N'
AND    ac.DT_AGENDA >= TRUNC(SYSDATE)

04

Colheita de metadados do DBAMV

roda uma vez no DBeaver

O pacote que dá à sessão Claude o conhecimento completo do esquema: todas as tabelas, colunas, tipagens, comentários, chaves e domínios do owner DBAMV. São só metadados e catálogos, sem dado pessoal: os CSVs podem ser commitados. Rode cada query no DBeaver, exporte o resultado como CSV (UTF-8, separador vírgula) e salve com o nome exato indicado em ana/api-mv/resultados/metadados/. Em 27/jul/2026 a sessão colheu os 8 arquivos pela conexão direta (enquanto ela funcionou); se o banco que você acessa no DBeaver for outro, rode de novo e substitua os arquivos.

M1 Catálogo de tabelas meta-1-tabelas.csv

O que entrega: as ~5.8 mil tabelas do DBAMV com volumetria (num_rows) e o comentário oficial de cada uma.

Salvar como meta-1-tabelas.csv
SELECT t.TABLE_NAME, t.NUM_ROWS,
       TO_CHAR(t.LAST_ANALYZED, 'YYYY-MM-DD') AS LAST_ANALYZED,
       c.COMMENTS
FROM   ALL_TABLES t
LEFT JOIN ALL_TAB_COMMENTS c
       ON c.OWNER = t.OWNER AND c.TABLE_NAME = t.TABLE_NAME
WHERE  t.OWNER = 'DBAMV'
ORDER  BY t.TABLE_NAME;

M2 Todas as colunas e tipagens meta-2-colunas.csv

O que entrega: as ~77 mil colunas do esquema, com tipo, tamanho, precisão e obrigatoriedade. É o arquivo que responde "essa coluna existe? qual o tipo?" para qualquer tabela.

Salvar como meta-2-colunas.csv
SELECT TABLE_NAME, COLUMN_ID, COLUMN_NAME, DATA_TYPE,
       DATA_LENGTH, DATA_PRECISION, DATA_SCALE, NULLABLE
FROM   ALL_TAB_COLUMNS
WHERE  OWNER = 'DBAMV'
ORDER  BY TABLE_NAME, COLUMN_ID;

M3 Comentários de colunas meta-3-comentarios-colunas.csv

O que entrega: os ~47 mil comentários oficiais do MV coluna a coluna: o dicionário semântico do sistema, direto da fonte.

Salvar como meta-3-comentarios-colunas.csv
SELECT TABLE_NAME, COLUMN_NAME, COMMENTS
FROM   ALL_COL_COMMENTS
WHERE  OWNER = 'DBAMV'
AND    COMMENTS IS NOT NULL
ORDER  BY TABLE_NAME, COLUMN_NAME;

M4 Chaves primárias meta-4-pks.csv

O que entrega: a PK de cada tabela (coluna a coluna, com posição): quem identifica cada linha.

Salvar como meta-4-pks.csv
SELECT c.TABLE_NAME, cc.COLUMN_NAME, cc.POSITION, c.CONSTRAINT_NAME
FROM   ALL_CONSTRAINTS c
JOIN   ALL_CONS_COLUMNS cc
       ON cc.OWNER = c.OWNER AND cc.CONSTRAINT_NAME = c.CONSTRAINT_NAME
WHERE  c.OWNER = 'DBAMV'
AND    c.CONSTRAINT_TYPE = 'P'
ORDER  BY c.TABLE_NAME, cc.POSITION;

M5 Chaves estrangeiras (o grafo do banco) meta-5-fks.csv

O que entrega: as ~11 mil FKs com tabela e coluna de origem e destino: o mapa de relacionamentos inteiro, que permite montar qualquer JOIN com segurança.

Salvar como meta-5-fks.csv
SELECT c.TABLE_NAME  AS TABELA_FILHA,
       cc.COLUMN_NAME AS COLUNA_FILHA,
       cc.POSITION,
       rc.TABLE_NAME  AS TABELA_PAI,
       rcc.COLUMN_NAME AS COLUNA_PAI,
       c.CONSTRAINT_NAME
FROM   ALL_CONSTRAINTS c
JOIN   ALL_CONS_COLUMNS cc
       ON cc.OWNER = c.OWNER AND cc.CONSTRAINT_NAME = c.CONSTRAINT_NAME
JOIN   ALL_CONSTRAINTS rc
       ON rc.OWNER = c.R_OWNER AND rc.CONSTRAINT_NAME = c.R_CONSTRAINT_NAME
JOIN   ALL_CONS_COLUMNS rcc
       ON rcc.OWNER = rc.OWNER AND rcc.CONSTRAINT_NAME = rc.CONSTRAINT_NAME
      AND rcc.POSITION = cc.POSITION
WHERE  c.OWNER = 'DBAMV'
AND    c.CONSTRAINT_TYPE = 'R'
ORDER  BY c.TABLE_NAME, c.CONSTRAINT_NAME, cc.POSITION;

M6 Domínios das colunas-chave de agendamento meta-6-dominios.csv

O que entrega: os valores reais em uso (com contagem) de TP_SITUACAO, TP_FORMA_AGENDAMENTO, TP_ITEM e TP_ATENDIMENTO: o que os códigos significam na prática desta base.

Salvar como meta-6-dominios.csv
SELECT 'IT_AGENDA_CENTRAL.TP_SITUACAO' AS DOMINIO,
       NVL(TO_CHAR(TP_SITUACAO), '(nulo)') AS VALOR, COUNT(*) AS QTD
FROM   DBAMV.IT_AGENDA_CENTRAL GROUP BY TP_SITUACAO
UNION ALL
SELECT 'IT_AGENDA_CENTRAL.TP_FORMA_AGENDAMENTO',
       NVL(TO_CHAR(TP_FORMA_AGENDAMENTO), '(nulo)'), COUNT(*)
FROM   DBAMV.IT_AGENDA_CENTRAL GROUP BY TP_FORMA_AGENDAMENTO
UNION ALL
SELECT 'ITEM_AGENDAMENTO.TP_ITEM',
       NVL(TO_CHAR(TP_ITEM), '(nulo)'), COUNT(*)
FROM   DBAMV.ITEM_AGENDAMENTO GROUP BY TP_ITEM
UNION ALL
SELECT 'ATENDIME.TP_ATENDIMENTO',
       NVL(TO_CHAR(TP_ATENDIMENTO), '(nulo)'), COUNT(*)
FROM   DBAMV.ATENDIME GROUP BY TP_ATENDIMENTO
ORDER  BY 1, 2;
