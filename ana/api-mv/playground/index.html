A aula: o caminho de um agendamento
Leia isto antes de apertar qualquer botão

Ninguém "cria uma consulta". A consulta (cardiologia, ortopedia...) e o exame (tomografia, ultrassom...) já existem no catálogo do hospital: no banco MV, cada um é uma linha da tabela ITEM_AGENDAMENTO. O que você cria de verdade é a marcação: pegar um horário livre da agenda de um médico e prendê-lo a um paciente. A API expõe esse caminho em passos, e cada passo devolve o id que o passo seguinte pede. A ordem é esta:

Como ler os passos: assim = você digita/escolhe assim = número que um passo ANTERIOR devolveu tracejado = opcional (sem tracejado é obrigatório)
1
Quem é o paciente
GET /pessoas · se não existir: POST /pessoas

A API confere o cadastro central de pacientes. Sem paciente, nada pode ser marcado em nome dele.

você envia cpf ou telefone (um dos dois basta)
recebe e guarda cpf confirmado (identifica o paciente daqui em diante)
2
O que ele quer (escolher do catálogo)
GET /consultas ou GET /exames

Busca por texto no catálogo. O campo "id" de cada item da resposta é o número mais importante do fluxo inteiro: quase todos os passos seguintes pedem ele.

você envia pesquisa (texto livre; vazio lista tudo)
recebe e guarda idItemAgendamento (o campo "id" do item escolhido)
3
Quem paga
GET /convenios

Todo agendamento tem um pagador. Particular NÃO é "sem convênio": é um convênio com flag particular: true e id próprio. Passar o idItemAgendamento filtra só os convênios aceitos naquele item.

você envia idItemAgendamento (do passo 2) pesquisa
recebe e guarda idConvenio
4
Qual plano do convênio
GET /convenios/{idConvenio}/planos

O convênio se subdivide em planos (Familiar, Empresarial...). Mesmo o particular tem um plano. Se houver um só, é ele.

você envia idConvenio (do passo 3, vai na URL) idItemAgendamento (do passo 2)
recebe e guarda idPlano
5
Quando (a busca de horários livres)
GET /agendas/v2

Com os três ids na mão, a API devolve os horários livres, agrupados por unidade e por médico. Cada horário da resposta carrega DOIS ids: o idHorario (o slot exato: médico + dia + hora) e o idAgenda (a agenda daquele dia do médico).

você envia idItemAgendamento idConvenio idPlano (passos 2, 3 e 4)
se quiser idPrestador turno dataInicial
recebe e guarda idHorario idAgenda (cada horário da lista traz os dois)
6
Os detalhes finais (dependem do tipo)
consulta: GET /consultas/tipos · exame: GET /exames/perguntas

Consulta: o hospital quer saber o "tipo de marcação": é a PRIMEIRA consulta ou um RETORNO? Isso é o idTipoMarcacao. Exame: responder a triagem obrigatória (grávida? marca-passo?) e, se exigido, anexar documentos (pedido médico).

consulta envia idAgenda (do passo 5)
e recebe idTipoMarcacao
exame envia idItemAgendamento (do passo 2) cpf (do passo 1)
e recebe respostas de triagem
7
Efetivar (a única escrita do caminho feliz)
POST /horarios/agendar

Junta tudo e grava. No banco, isso significa preencher o slot: o CD_PACIENTE do horário deixa de ser nulo. A resposta traz o protocolo e o id do agendamento, que você usa depois para listar (GET /agendamentos), remarcar (POST /horarios/reagendar) e cancelar (DELETE /agendamentos/{id}).

você envia cpf idItemAgendamento idConvenio idPlano idHorario (tudo dos passos 1 a 5)
conforme o caso idTipoMarcacao (se consulta) respostas (se exame) nrCarteira (se convênio)
recebe e guarda id do agendamento protocolo
idde onde vemo que significa
idItemAgendamentocampo id de /consultas ou /examesO QUE será agendado (a especialidade ou o exame). No MV: ITEM_AGENDAMENTO.CD_ITEM_AGENDAMENTO.
idConvenio/conveniosQuem paga. Particular também é convênio. No MV: CONVENIO.
idPlano/convenios/{id}/planosO plano dentro do convênio. No MV: CON_PLA.
idAgendacada horário de /agendas/v2A agenda de UM dia de UM médico. No MV: AGENDA_CENTRAL. Serve para buscar os tipos de consulta.
idHorariocada horário de /agendas/v2O slot exato (médico + dia + hora). No MV: IT_AGENDA_CENTRAL. É ele que o agendar ocupa.
idTipoMarcacao/consultas/tiposPrimeira consulta ou retorno (só para consulta, não para exame).
id (agendamento)resposta do agendar ou GET /agendamentosA marcação criada. Com ele você consulta o status, remarca e cancela.

Preciso criar uma consulta para agendar um horário, ou vice-versa?

Nenhum dos dois. Consulta se ESCOLHE do catálogo (passo 2) e horário se ESCOLHE da agenda (passo 5). Criar, você só cria o cadastro do paciente (passo 1, quando não existe) e a marcação final (passo 7). O agendar não cria consulta nem horário: ele OCUPA um horário que já existia, com uma consulta que já existia.

Qual a diferença entre tipo de marcação e horário?

Horário (idHorario) é o slot físico da agenda: Dr. Fulano, dia 10, 14h. Tipo de marcação (idTipoMarcacao) é uma etiqueta administrativa da consulta: primeira consulta, retorno, subsequente. O hospital cobra e organiza diferente cada tipo, por isso o agendar pede os dois quando é consulta.

E se eu chamar fora de ordem?

As leituras funcionam soltas (você pode buscar convênios sem ter buscado consulta), mas os filtros ficam vazios ou incompletos. Já o agendar (passo 7) exige os ids verdadeiros dos passos 2 a 6: com id inventado a API recusa (sucesso: false) ou dá erro 500.
