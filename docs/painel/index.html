04 — Anatomia de um agendamento

Onde cada ID nasce.

O segredo contra erros: o agente nunca digita IDs longos. Ele guarda um mapa no estado da conversa e o paciente escolhe por número.

Estado da jornada vive em custom_attributes.agendamento_estado da conversa no Chatwoot. O LLM só vê números amigáveis; o subfluxo resolve o ID real.

06 — Gestão de agendamentos

Consultar, remarcar, cancelar.

Jornadas que hoje nem existem. Toda escrita passa por confirmação — cancelar exige um "sim" inequívoco.

Consultar

  1. Valida o CPF
  2. Listar_agendamentos
  3. Lê a lista numerada
  4. Oferece a próxima ação

Remarcar

  1. Lista e escolhe qual
  2. Busca novos horários
  3. Confirma o "de / para"
  4. Reagendar → novo protocolo

Cancelar

  1. Lista e escolhe qual
  2. Confirmação reforçada
  3. Só com "sim" inequívoco
  4. Cancela e oferece reagendar
07 — Guardrails

O que mantém tudo seguro.

🔢

Zero IDs inventados

Horário, valor e protocolo só existem se vieram de uma ferramenta. O paciente escolhe por número.

✋

Confirmação em 3 camadas

Regra de prompt + parâmetro confirmado + um nó-gate determinístico antes de qualquer escrita.

🔒

LGPD

CPF e anexos só trafegam para a API de agenda. Nunca reenviados, descritos ou usados para outro fim. Resultado de exame nunca por chat.

🩺

Bloqueios clínicos

Triagem com impedimento (ex.: gravidez) ou item indisponível nunca são contornados — viram acolhimento + humano.

🔁

Sem duplicidade

Nunca reefetiva em retentativa cega. Em dúvida, confere via Listar_agendamentos antes de repetir.

🛟

Fallback total

Nenhum erro quebra a conversa: prefixos-sinal disparam a escalada humana já existente.
